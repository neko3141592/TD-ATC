# VVVF 本格シミュレーター学習ロードマップ

## 目的

このロードマップは、現在の列車シミュレーターを将来的に「VVVF インバータ、三相交流、誘導電動機、車両運動、音」までつながる本格的なシミュレーターへ発展させるための学習順序と実装順序をまとめたものです。

最初から実車レベルの完全再現を狙うと、電気回路、電磁気、制御工学、数値計算、音響の知識が一気に必要になります。そこで、学習と実装を段階に分けます。

最終目標は次の状態です。

- ノッチ、速度、勾配、編成質量から必要な牽引力を決める
- インバータが電圧、周波数、PWM パターンを決める
- 三相交流がモーターに入力される
- モーターがトルクを出す
- ギアと車輪を通して車両が加速する
- PWM、モーター回転、負荷変化から VVVF 音が出る

## 現在の実装との接続

現在の力行系は、おおまかに次の形になっています。

```text
powerNotch, speed
  -> TrainSpec.GetTractionDemandForceN(...)
  -> TractionSystemController
  -> CarTractionState.tractionForceN
  -> TrainController.ApplyPhysics()
  -> F = ma で速度と距離を更新
```

これは車両運動の入口としては良い構造です。VVVF 化すると、将来的には次のように分解します。

```text
powerNotch
  -> 目標加速度 / 目標トルク
  -> VVVF 制御器
  -> インバータ出力電圧・周波数・PWM
  -> モーターモデル
  -> 軸トルク
  -> ギア・車輪
  -> 牽引力
  -> 車両運動
```

最初は `TrainSpec` の力行力カーブを残したまま、その横に VVVF の内部状態を追加するのが安全です。いきなり既存の力行計算を置き換えるのではなく、次の順で置き換えます。

1. 既存の力行力はそのまま使い、VVVF 音だけ速度とノッチに同期させる
2. モーター回転数、電気周波数、すべりを計算状態として持つ
3. モータートルクを計算し、既存の力行力と比較できるようにする
4. 十分安定してから、力行力の本体をモーターモデル由来に切り替える

## 全体像

本格 VVVF シミュレーターは、次の 6 分野でできています。

| 分野 | 何を理解するか | シミュレーターでの役割 |
| --- | --- | --- |
| 数学 | 三角関数、ベクトル、微分積分、微分方程式 | 波形、回転、数値シミュレーション |
| 力学 | 力、加速度、仕事、エネルギー、回転運動 | 車両加速、車輪、ギア、トルク |
| 電気回路 | 電圧、電流、電力、RLC、交流 | インバータ、モーター入力 |
| 電磁気 | 磁界、電磁誘導、回転磁界 | 誘導電動機の原理 |
| 制御 | フィードバック、PI 制御、電流制御 | 目標トルクに追従させる |
| 音響・信号処理 | 周波数、倍音、FFT、サンプリング | VVVF 音の生成 |

## フェーズ 0: 高校物理前の準備

目標は「式に拒否反応を起こさず、シミュレーター内の値を単位付きで考えられる」状態です。

詳しい説明と例題は [VVVF_Phase0_PrePhysics.md](VVVF_Phase0_PrePhysics.md) にまとめています。

### 学ぶこと

- 単位
  - m, s, kg, N, W, V, A, Hz
  - km/h と m/s の変換
  - rpm と rad/s の変換
- 比例と反比例
  - 速度が 2 倍なら回転数も 2 倍
  - 同じ出力なら速度が上がるほど力は下がる
- グラフ
  - 横軸を速度、縦軸を牽引力にする
  - 横軸を時間、縦軸を周波数にする

### 実装課題

- 現在速度 `speedMS` を km/h 表示する
- 車輪半径から車輪回転数 rpm を出す
- ギア比からモーター回転数 rpm を出す

使う式:

```text
speedKmh = speedMS * 3.6
wheelAngularSpeedRadS = speedMS / wheelRadiusM
wheelRpm = wheelAngularSpeedRadS * 60 / (2 * pi)
motorRpm = wheelRpm * gearRatio
```

## フェーズ 1: 三角関数と波

VVVF は「周波数を変える装置」なので、最初の数学は三角関数です。

詳細教材: [VVVF_Phase1_Waves.md](VVVF_Phase1_Waves.md)

### 学ぶこと

- `sin`, `cos`
- 角度とラジアン
- 周期、周波数、角周波数
- 位相
- 3 つの波を 120 度ずらす意味

重要な式:

```text
angle = 2 * pi * frequencyHz * time
wave = sin(angle)
angularFrequency = 2 * pi * frequencyHz
```

三相交流:

```text
u = sin(angle)
v = sin(angle - 2*pi/3)
w = sin(angle + 2*pi/3)
```

### 実装課題

- Unity で `sin` 波を計算して値を Debug 表示する
- 3 相の `u, v, w` を計算するクラスを作る
- 周波数を時間とともに上げる
- 周波数を上げると音程が上がる簡単な音を鳴らす

### 到達目標

「Hz が上がると波が速く振動する」「三相交流は 120 度ずれた 3 本の波」という説明ができる。

## フェーズ 2: 車両運動と回転運動

モーターが出すのは直接の牽引力ではなく、回転の力であるトルクです。車輪とギアを通して牽引力になります。

詳細教材: [VVVF_Phase2_MotionAndTorque.md](VVVF_Phase2_MotionAndTorque.md)

### 学ぶこと

- 速度、加速度
- 力 `F = ma`
- 仕事、エネルギー、出力
- トルク
- 角速度
- ギア比

重要な式:

```text
forceN = massKg * accelerationMS2
powerW = forceN * speedMS
wheelTorqueNm = tractionForceN * wheelRadiusM
motorTorqueNm = wheelTorqueNm / gearRatio / efficiency
tractionForceN = motorTorqueNm * gearRatio * efficiency / wheelRadiusM
```

### 実装課題

- `tractionForceN` から必要なモータートルクを逆算する
- モータートルクから `tractionForceN` を再計算する
- 現在の `TrainSpec` の力行力カーブと、トルク由来の力行力を比較表示する

### 到達目標

「モーターのトルクがギアで増幅され、車輪半径で割られて牽引力になる」と説明できる。

## フェーズ 3: 電気の基礎

VVVF の V は Variable Voltage、F は Variable Frequency です。つまり電圧と周波数を変える制御を理解する必要があります。

詳細教材:

- [VVVF_Phase3_00_Electricity_Index.md](VVVF_Phase3_00_Electricity_Index.md)
- [VVVF_Phase3_01_ChargeVoltageCurrent.md](VVVF_Phase3_01_ChargeVoltageCurrent.md)
- [VVVF_Phase3_02_DCResistancePower.md](VVVF_Phase3_02_DCResistancePower.md)
- [VVVF_Phase3_03_ACRmsPhase.md](VVVF_Phase3_03_ACRmsPhase.md)
- [VVVF_Phase3_04_MagnetismAndCoils.md](VVVF_Phase3_04_MagnetismAndCoils.md)
- [VVVF_Phase3_05_TrainVVVFCurrent.md](VVVF_Phase3_05_TrainVVVFCurrent.md)

### 学ぶこと

- 電圧 V
- 電流 A
- 抵抗 ohm
- 電力 W
- 直流と交流
- 実効値と最大値
- 力率

重要な式:

```text
powerW = voltageV * currentA
powerW = sqrt(3) * lineVoltageV * lineCurrentA * powerFactor
```

三相交流では、単相よりも電力計算が少し変わります。

### 実装課題

- インバータ入力の直流電圧 `dcLinkVoltageV` を持つ
- 出力周波数 `outputFrequencyHz` を持つ
- 線間電圧 `lineVoltageV` を持つ
- 電流、電圧、力率から電力を概算する

### 到達目標

「電圧を上げると流せる電力が増える」「周波数を上げるとモーターの同期速度が上がる」と説明できる。

## フェーズ 4: PWM とインバータ

VVVF 音らしさの大部分は PWM から来ます。PWM は電圧を滑らかに変えるのではなく、高速な ON/OFF の比率で平均電圧を作る方法です。

### 学ぶこと

- スイッチング
- デューティ比
- キャリア波
- 正弦波 PWM
- 非同期 PWM
- 同期 PWM
- パルスモード切替
- キャリア周波数

基本イメージ:

```text
正弦波指令 > 三角波キャリア なら ON
正弦波指令 <= 三角波キャリア なら OFF
```

### 実装課題

- 三角波キャリアを作る
- 正弦波指令と比較して PWM の ON/OFF を作る
- キャリア周波数を変える
- 速度に応じて PWM モードを切り替える
- PWM のスイッチング周波数を音に反映する

### 最初に実装する PWM モード例

| 速度域 | モード | 音の特徴 |
| --- | --- | --- |
| 低速 | 非同期 PWM | 高い連続音が出やすい |
| 中速 | 同期 PWM | 音階のように変化しやすい |
| 高速 | 1 パルス制御 | 音が低く太くなる |

### 到達目標

「インバータは連続的な電圧を直接作るのではなく、高速なスイッチングで平均的に交流を作る」と説明できる。

## フェーズ 5: 三相交流と回転磁界

誘導電動機を理解するには、三相交流が回転磁界を作ることを理解する必要があります。

### 学ぶこと

- 三相交流
- 120 度位相差
- 固定子
- 回転子
- 極数
- 同期速度

重要な式:

```text
synchronousRpm = 120 * frequencyHz / poleCount
```

例:

```text
frequencyHz = 50
poleCount = 4
synchronousRpm = 120 * 50 / 4 = 1500 rpm
```

### 実装課題

- モーター極数 `poleCount` を `CarSpec` か新しい `MotorSpec` に持たせる
- インバータ周波数から同期回転数を計算する
- 実際のモーター回転数と同期回転数を比較する

### 到達目標

「周波数を変えると回転磁界の速度が変わり、モーターの目標回転数が変わる」と説明できる。

## フェーズ 6: 誘導電動機の基礎

鉄道車両の VVVF 制御では、誘導電動機または同期電動機が使われます。まずは誘導電動機から始めるのが理解しやすいです。

### 学ぶこと

- すべり
- 回転磁界
- 電磁誘導
- トルク
- トルク-速度特性
- 始動時に大電流が流れる理由
- 高速域でトルクが落ちる理由

重要な式:

```text
slip = (synchronousRpm - rotorRpm) / synchronousRpm
```

注意:

- 停止中は `rotorRpm = 0` なので、すべりが大きい
- 回転子が同期速度に近づくと、すべりが小さくなる
- すべりがゼロだと誘導電動機はトルクを出しにくい

### 実装課題

- `synchronousRpm` と `motorRpm` から `slip` を計算する
- すべりが大きすぎる時は電流制限を入れる
- すべりが小さい時はトルクが落ちる簡易モデルを作る

最初の簡易トルクモデル:

```text
torque = maxTorque * slip / (slip + slipShape)
```

これは実機の正確な式ではありませんが、まず「すべりがトルクに関係する」ことを実装で確認できます。

### 到達目標

「誘導電動機は、回転磁界と回転子の速度差でトルクを出す」と説明できる。

## フェーズ 7: V/f 制御

最初の本格制御は V/f 制御を目標にします。これは、周波数を上げると電圧も上げて、モーターの磁束を大きく変えないようにする考え方です。

### 学ぶこと

- V/f 一定制御
- 基底周波数
- 基底電圧
- 低速電圧補償
- 定トルク領域
- 定出力領域

基本式:

```text
voltageCommandV = ratedVoltageV * frequencyHz / baseFrequencyHz
```

ただし最大電圧を超えないようにします。

```text
voltageCommandV = min(voltageCommandV, ratedVoltageV)
```

### 実装課題

- `MotorSpec` を作る
  - `ratedPowerW`
  - `ratedVoltageV`
  - `baseFrequencyHz`
  - `poleCount`
  - `maxTorqueNm`
  - `maxCurrentA`
- `InverterSpec` を作る
  - `dcLinkVoltageV`
  - `maxOutputCurrentA`
  - `carrierFrequencyHz`
  - `pwmMode`
- 周波数指令から電圧指令を計算する
- 基底周波数以上では電圧を固定し、弱め界磁のようにトルクを下げる

### 到達目標

「低中速では V/f を保ってトルクを出し、高速では電圧上限に当たるのでトルクが落ちる」と説明できる。

## フェーズ 8: 電流制御とトルク制御

実車に近づけるには、単に周波数を決めるだけではなく、必要なトルクに合わせて電流を制御する必要があります。

### 学ぶこと

- フィードバック制御
- PI 制御
- 目標値と実測値
- 電流制限
- 空転・滑走
- トルク指令

最小の PI 制御:

```text
error = target - actual
integral += error * dt
output = kp * error + ki * integral
```

### 実装課題

- 目標トルク `targetTorqueNm` を作る
- 実トルク `actualTorqueNm` を遅れて追従させる
- 電流上限でトルクを制限する
- ノッチを上げた時にトルクが瞬時に変わらず、少し遅れて立ち上がるようにする

### 到達目標

「制御は、目標値と現在値の差を見て指令を修正する仕組み」と説明できる。

## フェーズ 9: 音響モデル

音を後付けの効果音にせず、シミュレーション状態から生成するのが本格化の重要ポイントです。

### 学ぶこと

- 周波数と音程
- 倍音
- サンプリング周波数
- エイリアシング
- FFT
- フィルタ
- 音量包絡

音の入力に使う状態:

- キャリア周波数
- PWM モード
- 出力周波数
- モーター回転数
- トルク
- 電流
- ノッチ
- 回生か力行か

### 実装課題

- `VVVFAudioState` を作る
- インバータの状態から音の周波数成分を決める
- PWM モード切替時に音が段階的に変わるようにする
- 力行時と回生時で音色を変える

### 到達目標

「音源ファイルをただ再生する」のではなく、「インバータ状態から音が決まる」構造にする。

## フェーズ 10: 実車データとの比較

本格的にするほど、現実との比較が必要になります。ただし実車の制御定数は公開されていないことが多いので、完全一致よりも物理的に破綻しないことを優先します。

### 集めるデータ

- 編成質量
- 電動車比
- モーター出力
- ギア比
- 車輪径
- 最高速度
- 起動加速度
- 減速度
- VVVF 音の録音
- 速度ごとの音の変化

### 比較するグラフ

- 時間-速度
- 速度-加速度
- 速度-牽引力
- 速度-モーター回転数
- 時間-出力周波数
- 時間-キャリア周波数

### 到達目標

実車と完全一致しなくても、次の関係が自然になる。

- 低速では加速度が比較的大きい
- 高速では加速度が落ちる
- 周波数は速度とともに上がる
- PWM モード切替で音が変わる
- 回生ブレーキ時は力行時と違う音になる

## 推奨する実装アーキテクチャ

いきなり巨大なクラスを作らず、役割ごとに分けます。

```text
TrainController
  車両全体の速度、距離、運動方程式

TractionSystemController
  編成内の M 車へ力行を分配する

VVVFController
  ノッチ、速度、目標トルクからインバータ指令を作る

InverterModel
  電圧、周波数、PWM、キャリア周波数を計算する

MotorModel
  周波数、電圧、回転数、すべりからトルクを計算する

GearWheelModel
  モータートルクを車輪の牽引力に変換する

VVVFAudioSource
  インバータ状態から音を生成する
```

推奨データ構造:

```text
MotorSpec : ScriptableObject
InverterSpec : ScriptableObject
VVVFControlProfile : ScriptableObject
MotorRuntimeState : class
InverterRuntimeState : class
VVVFAudioState : struct/class
```

## 最初に作るべき実装マイルストーン

### Milestone 1: モーター回転数の可視化

既存の速度から、車輪 rpm とモーター rpm を出すだけです。

完了条件:

- 停止時は 0 rpm
- 速度が 2 倍になると rpm も 2 倍
- ギア比を変えるとモーター rpm が変わる

### Milestone 2: 同期速度とすべりの計算

インバータ周波数を仮に作り、同期 rpm とすべりを計算します。

完了条件:

- 周波数を上げると同期 rpm が上がる
- 実 rpm が同期 rpm に近づくとすべりが小さくなる
- すべりが異常値になった時に clamp する

### Milestone 3: V/f 制御

速度または目標 rpm から周波数を決め、周波数から電圧を決めます。

完了条件:

- 低速から中速では周波数と電圧が一緒に上がる
- 定格電圧に達した後は電圧が頭打ちになる
- 電圧、周波数、モーター rpm を画面またはログで確認できる

### Milestone 4: 簡易誘導電動機トルク

すべりと電圧からトルクを作り、既存の `TrainSpec` 力行力と比較します。

完了条件:

- 停止直後にトルクが出る
- 高速域でトルクが落ちる
- 電流またはトルク上限を超えない

### Milestone 5: 牽引力の置き換え

簡易モーターモデル由来の牽引力で列車を動かします。

完了条件:

- 低速で急に暴れない
- 最高速度付近で自然に加速が鈍る
- 勾配抵抗とブレーキとの合成で破綻しない

### Milestone 6: VVVF 音の状態連動

インバータ状態から音を出します。

完了条件:

- ノッチオフで音が消える、または惰行音に変わる
- 周波数上昇に合わせて音が変化する
- PWM モード切替で音色が変わる
- フレームレートに左右されにくい

## 実装時の注意

### 単位を必ず名前に入れる

良い例:

```csharp
float speedMS;
float voltageV;
float currentA;
float torqueNm;
float frequencyHz;
```

悪い例:

```csharp
float speed;
float voltage;
float torque;
```

VVVF では単位ミスが非常に起きやすいので、変数名に単位を入れる方が安全です。

### 物理計算と音を分ける

音のために物理を壊さないようにします。

```text
物理状態
  -> tractionForceN
  -> train motion

物理状態のコピー
  -> audio parameters
  -> VVVF sound
```

### まずは安定性を優先する

本格的な式を入れても、数値的に暴れるとシミュレーターとして使えません。

- `dt` を使う
- ゼロ割りを避ける
- `Mathf.Clamp` で範囲制限する
- 急変させず `MoveTowards` や `Lerp` で追従させる
- 低速域は特別扱いする

### 実車と完全一致させようとしすぎない

実車の制御パラメータは公開されていないことが多いです。まずは物理的に自然な挙動を作り、録音や公開スペックに合わせて調整します。

## 用語メモ

| 用語 | 意味 |
| --- | --- |
| VVVF | Variable Voltage Variable Frequency。電圧と周波数を変える制御 |
| インバータ | 直流を交流に変換する装置 |
| PWM | 高速 ON/OFF で平均電圧を作る方式 |
| 三相交流 | 120 度ずれた 3 本の交流 |
| 誘導電動機 | 回転磁界と電磁誘導で回るモーター |
| 同期速度 | 回転磁界の回転速度 |
| すべり | 同期速度と回転子速度の差の割合 |
| V/f 制御 | 周波数に比例して電圧を変える制御 |
| 定トルク領域 | 低中速でほぼ一定トルクを出せる領域 |
| 定出力領域 | 高速で出力一定、トルクが下がる領域 |
| 弱め界磁 | 高速域で磁束を弱めて回転数を伸ばす制御 |

## 当面の具体的な次ステップ

次に実装するなら、順番は次がよいです。

1. `MotorSpec` を作る
2. `InverterSpec` を作る
3. `CarTractionState` に `motorRpm`, `synchronousRpm`, `slip`, `motorTorqueNm` を追加する
4. 既存の力行力は変えずに、まず各値を計算して HUD または Debug に出す
5. V/f 制御で `frequencyHz` と `voltageV` を出す
6. 簡易トルクモデルを作って、既存の力行力と比較する
7. 問題がなければ、力行力の計算元を段階的に切り替える

この順番なら、現在のシミュレーターを壊さずに本格 VVVF へ近づけられます。
